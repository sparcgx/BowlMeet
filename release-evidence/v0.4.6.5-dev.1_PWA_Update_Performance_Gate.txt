Base: stable/v0.4.6.4 @ 01a04ebf3a166bca6bd6e1cc51cf3f324f6d5a05
Scope: optimize update latency without weakening backup/snapshot safety gates.

Optimization:
- Reuse one captured state per backup/update phase.
- persistDbStateNow accepts a shared state snapshot instead of re-capturing it.
- State/meta writes use one IndexedDB transaction via idbPutMany.
- createSnapshot can skip duplicate persist when caller already persisted the exact same state.
- createSnapshot can skip renderSafety on the update critical path.
- Backup JSON reuses the exact state used for the safety snapshot.
- Safety UI refresh is deferred until after the backup gate is unlocked.
- Final update still captures the latest state, persists it once, and creates a final snapshot.
- Manual no-update feedback delay reduced from 900ms to 400ms and avoids firing while a worker is installing.

Expected critical-path reduction:
- Backup phase: duplicate DB persist removed; duplicate captureState removed; blocking safety UI refresh removed.
- Apply phase: duplicate DB persist removed; blocking safety UI refresh removed.
- Safety layers retained: user backup snapshot + full JSON + final pre-activation snapshot.

- DB_VERSION = 2
- PUBLIC/PIN unchanged
- Supabase / IndexedDB schema unchanged
- Dynamic Grid / Ranking / Awards / Share unchanged
- Score model 1-6 unchanged
