## Executed gates

- Node source/scoring/simulated SW: **25 PASS / 0 FAIL**.
- Offline Chromium DOM/CSS/UI: **248 PASS / 0 FAIL**.
- 2,000 seeded valid bowling games matched an independent scoring function; this counts as one property test, not 2,000 separate gates.
- Desktop/mobile widths: 320, 390, 430, 768, 1440 CSS pixels.
- Themes: default, Liquid Glass, Clear Blue, Soft Violet, Dark Night, High Contrast.
- Tests include navigation clicks, public-only fixtures, cancelled-public tombstones, invalid-score rejection, reduced motion, pagehide pause, fixed mobile Dock and no horizontal overflow.
- No duplicate DOM IDs, duplicate function declarations or missing literal DOM ID references in the baseline static scan.
- Inline application JS is bit-identical after masking only APP_VERSION and the three deliberately changed UI functions: validateSheet, renderAll and switchView.
- SQL files unchanged: True.

The browser harness inlines source assets, uses a mock localStorage, blocks all external requests, and exercises IndexedDB fallback. It is **not native IndexedDB/PWA/Safari validation**.
The SW tests simulate Cache API and fetch in Node; they are **not** a real offline-upgrade device gate.

## Remaining risks / deferred work

1. **Startup state arbitration (P1, needs fault injection):** initDataSafety applies a saved IndexedDB appState when present. A more recent localStorage fallback after a failed IDB write may need reconciliation. This audit did not change restore/startup data-selection rules or certify that race as fixed.
2. **localStorage quota (P1, needs fault injection):** synchronous persist/saveDraft calls can throw before queued IDB persistence. Do not clear app data as a workaround. A transactional/recovery change requires a dedicated data-safety branch and tests.
3. **Large history view (P2):** opening History still renders the full list. Pagination/windowing is a next step; this patch only stops rendering hidden views.
4. **Monolith and CSS debt (P2):** baseline index is 529,721 bytes with 139,909 bytes of inline CSS and 306,052 bytes of inline JS. Presentation hardening is a final-layer patch, not a full cascade/architecture rewrite.
5. **Cloud / RLS (unverified here):** no real Supabase data writes, policy changes or production load tests were executed. Public-only fixture tests do not replace live RLS verification.
6. **Physical acceptance pending:** iPhone Safari, installed PWA update with/without optional backup, offline relaunch, native backup round-trip, and keyboard/safe-area behavior.
7. **Release governance:** main and Stable have different histories/evidence contents. Do not force-reset Freeze to make refs look identical. New release evidence should be finalized before an immutable Freeze is established.
